## 问题 1：生成的英文太少，而且过于重复

### 现象描述
用户生成五个视频，单词 `product`、`market` 等反复出现，希望单词数量在 8～20 个之间随机，内容更丰富。

### 根因分析

**位置**：`packages/backend/src/services/content.service.ts`

**核心问题**：`buildCandidates()` 函数中存在一个硬编码的 `NARRATIVE_WORDS` 常量数组（第 85-112 行），包含 20 个固定词汇（`product`、`improve`、`provide`、`opportunity`、`risk`、`market`、`establish`、`support`、`contract`、`create`、`require`、`resolve`、`perform`、`propose`、`consequence`、`emphasis`、`finally`、`staff`、`expectation`、`alternative`、`object`、`resume`、`elect`、`calculate`、`convention`、`reverse`）。

这段代码的逻辑是：
1. 先让 LLM 列出 15 个主题相关词（第 63-79 行 `fetchTopicWords`）
2. 然后**无条件**将 `NARRATIVE_WORDS` 全部推入候选池（第 175-176 行）
3. 最后用高频池随机补足（第 179-182 行）

**导致重复的原因**：
- `NARRATIVE_WORDS` 是固定列表，每次生成都会加入候选池，导致 `product`、`market` 等词在每个视频中反复出现
- LLM 产出的主题词经过词库校验后，实际匹配数可能很少（模型不产出词库中存在的词）
- `target = Math.min(want * 2, MAX_WORDS_PER_CONTENT)` 中 `want` 默认 8，`target` = 16，但实际注入词数受 `MAX_WORDS_PER_CONTENT = 20` 限制

### 期望行为
- 单视频英文词数量在 8～20 个之间随机
- 词汇内容丰富，不总是固定几个词

## 问题 2：上传标记弹窗第一次点击显示旧标记

### 现象描述
生成记录中每次第一次点击标记按钮，弹出的对话框会存在原来的标记信息，第二次点击又不存在了。希望第一次点击就是空白的，只有点击到有标记的才显示它自己的标记信息。

### 根因分析

**位置**：`packages/frontend/src/components/upload-mark-manager.vue`

**核心问题**：组件的 `marks` ref 在不同文件间切换时未被清空。

```typescript
// 第 59-61 行
const open = ref(false);
const loading = ref(false);
const marks = ref<UploadMark[]>([]);  // ← 全局状态，组件实例复用时残留
```

```typescript
// 第 93-96 行
function onOpenChange(v: boolean): void {
  open.value = v;
  if (v) void load();  // ← 仅设置 loading，未先清空 marks
}
```

**触发路径**：
1. 用户在文件 A 打开标记弹窗 → `load()` 异步请求 A 的标记 → `marks` 赋值为 A 的标记
2. 关闭弹窗 → `open.value = false`，但 `marks` 仍保留 A 的标记
3. 用户在文件 B 打开标记弹窗 → `onOpenChange(true)` 触发 → `loading = true` → `load()` 异步请求 B 的标记
4. **在 `load()` 完成之前**，模板已渲染 `marks`（仍是 A 的标记），因为 `v-if="loading"` 仅在 `loading` 为 true 时显示加载态，但 `load()` 中 `loading.value = true` 后立即 `await listUploadMarks(...)`，此间 `marks` 仍是旧值

**为什么第二次点击正常**：第二次点击时 `marks` 已被第一次 `load()` 更新为 B 的标记，`load()` 又请求一次 B 的标记，覆盖后一致。

### 期望行为
- 弹窗打开时 `marks` 应立即清空
- 或 `filename` 变化时 watches 并 reload + 清空

## 问题 3：文件管理中清理未引用只清理视频，未清理音频

### 现象描述
清理未引用内容时只清理了视频，音频没有清理，每次都需要手动清理。希望清理非 bgm 且没有引用的相关视频和音频，但 bgm 一定不要动。

### 根因分析

**位置**：`packages/frontend/src/views/Files.vue`

**核心问题**：`openCleanup()` 和 `doCleanup()` 过滤条件仅包含 `video` 类型。

```typescript
// 第 95-103 行
function openCleanup(): void {
  const orphans = filtered.value.filter((f) => f.type === "video" && f.referencedBy.length === 0);
  // ...
}

// 第 105-119 行
async function doCleanup(): Promise<void> {
  const orphans = filtered.value.filter((f) => f.type === "video" && f.referencedBy.length === 0);
  // ...
  const result = await batchDeleteFiles(
    orphans.map((f) => ({ filename: f.filename, type: "video" as const })),
  );
  // ...
}
```

**后端能力**：`packages/backend/src/routes/file-manager.ts` 的 `batchDeleteRoute` 已支持 `audio`、`video`、`bgm` 三种类型，只需前端传递正确的 type 即可。

### 期望行为
- 清理范围：`type === "video" || type === "audio"` 且 `referencedBy.length === 0`
- BGM 素材（`type === "bgm"`）绝对不动
- 清理提示语需明确告知用户将清理视频和音频

## 问题 4：修改时视频/文案中带"修改"类文字

### 现象描述
每次修改时在视频、文案中都会带"修改"之类的文字，希望这只是一个标记，而不是放到数据库中作为最终文案做整个视频的渲染。

### 根因分析

**位置**：`packages/backend/src/routes/tasks.ts`（PATCH 路由）+ `packages/frontend/src/components/audit-panel.vue` + `packages/frontend/src/components/audit-row.vue`

**核心机制**：
1. 后端 `PATCH /api/tasks/:id` 处理器（`tasks.ts` 第 277-305 行）在每次更新时向 `audit.modifications` 数组追加一条记录：
   ```typescript
   const changed = ["title", "content", "audio", "video", "status"].filter((f) => f in body);
   const modifications = [
     ...(Array.isArray(audit?.modifications) ? audit.modifications : []),
     { at: new Date().toISOString(), fields: changed },
   ];
   ```
2. 该 `audit` 对象与 `content` 字段**分开存储**在 `contents` 表的 `audit` JSON 列中（`schema.ts` 第 31 行）
3. 前端在 `AuditPanel`（`audit-panel.vue`）和 `AuditRow`（`audit-row.vue`）中展示"修改日志"，标签为"修改日志"，内容为修改时间和字段名

**关键发现**：
- `audit.modifications` 存储在 `contents.audit` 字段，**不是** `contents.content` 字段
- 视频渲染使用 `content` 字段（见 `video.service.ts` 第 212 行 `renderVideo(dto: ContentDTO)`），**不读取** `audit` 字段
- 文案生成（TTS）使用 `content` 字段（见 `tts.service.ts` 第 303 行 `buildTtsText`），**不读取** `audit` 字段
- 因此，"修改"文字**理论上不应该**出现在最终视频或文案中

**可能的原因**：
1. 用户在前端看到 AuditPanel 中的"修改日志"标签，误以为是视频/文案的一部分
2. 或者存在尚未发现的代码路径将 `audit` 数据混入了 `content`
3. 或者用户不希望修改日志功能将数据写入数据库

### 期望行为
- "修改"仅作为 UI 标记（前端展示），不写入数据库
- 或：修改日志与内容彻底分离，确保不进入渲染管线

## 问题 5：AI 推荐按钮需要 loading，其他地方也需要观察

### 现象描述
在新建视频中点击 AI 推荐按钮需要 loading，不能没有任何交互。其他地方也需要观察是否需要加入 loading 来提升产品的舒适性。

### 根因分析

**位置**：`packages/frontend/src/views/CreateTask.vue`

**当前状态**：AI 推荐按钮**已有** loading 状态：

```typescript
// 第 47-48 行
const suggestedTopics = ref<{ title: string; description: string }[]>([]);
const suggesting = ref(false);

// 第 185-196 行
async function suggest(): Promise<void> {
  suggesting.value = true;  // ← 设置 loading
  // ...
  finally {
    suggesting.value = false;  // ← 清除 loading
  }
}
```

```vue
<!-- 第 540-547 行 -->
<button
  type="button"
  class="shrink-0 rounded-lg bg-purple-600 px-4 py-2 text-sm font-medium text-white hover:bg-purple-700 disabled:opacity-50"
  :disabled="suggesting"
  @click="suggest"
>
  {{ suggesting ? "推荐中…" : "✨ AI 推荐" }}
</button>
```

**按钮已禁用 + 文字切换为"推荐中…"，但无视觉 loading 图标（如 spinner）**。用户可能期望更明显的视觉反馈。

### 其他需要 loading 的地方

| 位置 | 当前状态 | 建议 |
|------|---------|------|
| `CreateTask.vue` 生成视频按钮 | `step` 状态控制，按钮文字"处理中…" | 已有，但无 spinner |
| `CreateTask.vue` 配音按钮 | `step === 'tts'` 控制 | 已有文字，建议加 spinner |
| `CreateTask.vue` 渲染按钮 | `step === 'rendering'` 控制 | 已有文字，建议加 spinner |
| `CreateTask.vue` 保存修改 | `saving` 控制，按钮文字"保存并重新配音渲染中…" | 已有，建议加 spinner |
| `TaskDetail.vue` 重新配音 | `revoicing` 控制 | 已有文字，建议加 spinner |
| `TaskDetail.vue` 保存修改 | `saving` 控制 | 已有文字，建议加 spinner |
| `Files.vue` 刷新 | `loading` 控制 | 已有"加载中…"文字 |
| `Files.vue` 清理未引用 | 无独立 loading，依赖 `batchDeleteFiles` | 建议加 spinner |
| `TaskList.vue` | 需确认 | 建议审查 |

### 期望行为
- 所有异步操作按钮添加 spinner 图标
- 按钮在 loading 期间禁用
- 全局 loading 状态可复用（如 `useLoading` composable）

|---|------|---------|---------|------------|
| 1 | 英文词少且重复 | `content.service.ts` | 高 | 移除硬编码 `NARRATIVE_WORDS`，改为从词库随机抽取 + LLM 主题词加权 |

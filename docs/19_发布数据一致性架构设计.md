## 一、现状对比：「一集视频」在系统里有五个锚点

```
                      ┌─ 文件管理 ─→ uploads/video/*.mp4（磁盘真相）        44
                      ├─ 发布管理 ─→ contents（listTasks pageSize:100）    43
「一集」的锚点 ────────┼─ 视频资产 ─→ contents WHERE video IS NOT NULL     43
                      ├─ 上传标记 ─→ upload_marks                          42
                      └─ 数据分析 ─→ publish_records INNER JOIN contents   39
```

五个锚点彼此**没有约束、没有对账、没有互相通知**。其中两条链路是本次要接通的：

- `upload_marks` ↔ `publish_records`：语义上是同一件事（"这集发出去了"）的两个记录，代码上完全脱钩 → **C2 的根因**
- `contents.title` ↔ `video_analytics.story_topic`：后者是前者的可覆盖快照，但读取端把「快照为 NULL」当成了「标题为空」 → **C1 的根因**

## 二、根因（四条，全部带行号证据）

### R1　快照 NULL 被当成标题为空，且兜底链被前端二次摧毁

| 位置 | 代码事实 | 后果 |
|------|---------|------|
| `packages/backend/src/routes/video-analytics.ts:99` | `storyTopic: analytics ? analytics.storyTopic : getStoryTopic(content)` | 只要 `video_analytics` 行存在就只认快照列；快照为 NULL 时**永不回落**到生成标题 |
| `packages/frontend/src/lib/analytics-state.ts:93` | `storyTopic: saved.storyTopic ?? ""` | 服务端 `null` 被固化成空串，覆盖掉 `Analytics.vue:59` 来自 `task.title` 的本地兜底 |
| `packages/frontend/src/views/Analytics.vue:358` | `metaFor(task).storyTopic \|\| "未命名"` | 空串 → 「未命名」 |
| `packages/backend/src/routes/video-analytics.ts:54-58` | `getStoryTopic` 优先级 `style.introTopic → audit.input.topic → contents.title` | 即使没有快照，也优先显示**输入主题**而非生成后的标题，与用户预期相反 |

生产实证：`video_analytics` 共 5 行，其中 `cnt_20261002_469bc3` 的 `story_topic` 为 NULL（生成标题《线上学习的新支持》）→ 显示「未命名」；`cnt_20260919_8e02dc` 快照为「选修课翻车」而生成标题是「选修课的冲突」→ 这是用户显式改过的，**必须保留覆盖语义**。

### R2　上传标记与发布记录是两套事实源

`packages/backend/src/routes/upload-marks.ts:302-346` 的创建处理器只 `INSERT upload_marks`，从不调用 `createPublishRecord`（`packages/backend/src/services/analytics-metrics.service.ts:299-339`）。发布记录只能在「数据接入」页手工建、或导入向导匹配时产生。

生产实证：42 个真实集**全部有上传标记**，但只有 38 个有发布记录；09-29~10-02 四集因此在数据分析不可见。

**扇出量化（决定改动落点）**：5 个视图（`MarksList`/`Files`/`TaskList`/`AuditList`/`VideoList`）→ 1 个组件 `upload-mark-manager.vue:174` → 1 个 API 封装 `client.ts:384` → **1 个后端处理器**。
因此派生逻辑必须落在后端处理器：一处改动覆盖全部 5 个入口与未来任何 API 直调；落在前端则要改 1 个组件但仍漏掉所有非 UI 调用方。**不做前端派生。**

### R3　数据分析的行集锚点会静默吞集

`packages/backend/src/services/analytics-dashboard.service.ts:449-458` 以 `publish_records` 为 FROM 起点 `INNER JOIN contents`；`:602` 的 `total` 又直接 `COUNT(publish_records)`。没有发布记录的集不是「排在后面」，是**根本不在行集里**，界面上没有任何痕迹。

### R4　列表硬顶 + KPI 用已加载条数

| 位置 | 事实 | 风险 |
|------|------|------|
| `Analytics.vue:254` | `listTasks({ pageSize: 100 })`，页面不分页 | 第 101 集起整行不可见 |
| `Analytics.vue:341` | KPI「视频总数」= `tasks.length`（已加载数） | 截断被掩盖，`total` 字段被丢弃 |
| `TaskList.vue:187` | 同样只拉 100 条后做客户端分页 | 服务端 `total` 与实际装载行数不一致，尾页空转 |

按用户一天一集的节奏，**约 2026-12 中旬触发**，且会以「又看不见几集」的形态复现——与本次事故同形。

## 三、模块设计

### M1　标题解析单一口径（后端一处，前端一处）

新增纯函数（与 `getDuration` 同区，`video-analytics.ts`）：

```
resolvePublishTitle(content, analytics):
  analytics?.storyTopic 非空 → 用它            （用户显式覆盖，最高优先）
  否则                      → content.title    （生成后的标题）
```

- `buildResponse:99` 改调该函数；**移除** `getStoryTopic` 中 `style.introTopic` / `audit.input.topic` 作为标题来源的分支。
  减法说明：`introTopic` 是片头主题、`audit.input.topic` 是生成入参，两者都不是"这一集叫什么"。它们已有各自的展示位（详情页片头设置 / 审计档案），不该冒充列表标题。这是本次唯一的行为收窄，且方向与用户诉求一致。
- 前端 `mergeServerAnalyticsMeta:93` 改为 `storyTopic: saved.storyTopic ?? local.storyTopic`——服务端没有显式值时保留本地（=生成标题）兜底，不再固化成空串。
- `Analytics.vue:358` 的「未命名」字面量删除，回落链在数据层已闭合；真出现空标题（`contents.title` NOT NULL，理论不可达）显示 `contentId` 而非「未命名」，便于定位而不是掩盖。
- 契约不变：`storyTopic` 字段名/类型/可选性不动（AGENTS.md §1.1 禁改已发布契约），只改其取值语义，并在 `docs/11` 与 `docs/17` 注明。

**测试**：后端 `resolvePublishTitle` 三分支纯函数用例（覆盖值/NULL/空串）；前端 `mergeServerAnalyticsMeta` 保留本地兜底用例；`Analytics.vue` 标题列渲染用例断言不出现「未命名」。

### M2　标记即发布（后端单点派生）

在 `upload-marks.ts` 创建处理器内，**与 INSERT 标记同一事务**派生发布记录：

```
派生规则（幂等，可重放）：
  contentId      = 已解析的 taskId（现有逻辑 :313-323，含按文件名反查）
  platform       = 标记 platform（同源自由文本，不新增枚举）
  platformVideoId = extractWorkIdFromUrl(url, platform)   ← 复用 lib/import-matcher.ts:199，不新写解析器
  publishTitle   = contents.title
  publishTime    = 标记 createdAt（标记动作即"已发布"的时间证据；不猜测真实平台发布时间）
  videoAssetId   = 标记 videoFilename
  publishStatus  = "published"
```

- **幂等键**：先按 `(contentId, platform)` 查已有记录；命中则只在字段更空时补齐（`platformVideoId`/`videoAssetId`/`publishTitle`），不新增行；未命中才插入。避免 `uq_publish_records_platform_video` 在 `platform_video_id IS NULL` 下不约束唯一而产生的重复行。
- **无链接的标记**：`platformVideoId` 保持 NULL，**不伪造作品 ID**（与既有诚实纪律一致）。该行进入数据分析但指标为空，靠 M3 的提示可见。
- **PATCH / DELETE 标记不联动删除发布记录**：指标（`video_metrics`/`video_metric_daily`）以 `publishRecordId` 为键，删记录会连带毁掉已导入的历史指标。删除标记只删标记；发布记录由数据接入页显式管理。此不对称须在 `docs/17` 写明，否则将被误读为 bug。
- 派生失败**不静默**：与标记写入同事务，失败则整体回滚并返回明确错误（不出现"标记成功但分析里没有"的新裂缝）。

**测试**：派生纯函数（URL→ID、幂等键决策、字段补齐三态）单测；路由用例覆盖「创建标记→发布记录出现」「重复标记不产生第二条」「无链接派生 NULL」「派生失败标记不落库」。

### M3　未登记可见性（**取代**原拟的行集改造）

原拟把 `/insights/videos` 行集从 `publish_records` 改为 `contents` 驱动 + LEFT JOIN。**M2 落地后此改动收益消失**：派生规则保证「有标记 ⇒ 有发布记录」，因此仍无发布记录的集正是"从未标记发布"的集——它本来就没有平台侧数据可分析，出现在视频表现列表里只会是一行全「—」的噪音。

改为承担可见性而非改锚点，成本低一个数量级：

- 后端只读端点/字段：`GET /api/analytics/videos` 响应追加 `unregisteredContentCount`（`contents` 中有成片但无发布记录的集数），与 `total` 同查询批内得出，不新增往返。
- 前端 `InsightsVideos.vue` 顶部提示条：「另有 N 集未标记发布 —— 去上传标记」并给跳转。N=0 时不渲染。
- `:602` 的 `total` 与 items 行集锚点保持同源（现状已同源，仅补断言用例钉住，防止将来改坏）。

### M4　计数与分页诚实化

- `Analytics.vue`：KPI 改用服务端 `total`；`listTasks` 循环取回全部页（`pageSize=100` 上限是后端 `tasks.ts:39` 的校验，不改契约），或在页面加真分页。**取前者**：发布管理是"逐集编辑元数据"的工作台，需要一次性看到全集，翻页会把工作流打断；行数上限由循环保证。
- `TaskList.vue`：同样以循环取全量替换"只拉第一页"，客户端分页保留（该页有批量选择语义，全量在内存更合理）。
- 两处共用一个 `listAllTasks()` 封装（`client.ts`），不各写一份循环。
- 断言用例：`total > 100` 时 KPI 数字等于 `total` 且行数等于 `total`。

### M5　数据修复（开发库演练 → 交付脚本，不写生产）

脚本按依赖顺序分三段，**每段幂等、可重放、带前后对账查询**：

1. **清夹具**：删除 `contents.id LIKE 'test%'` 及其在 `publish_records`/`upload_marks`/`video_analytics`/`content_features`/`video_segments`/`import_*` 的关联行。夹具 `test0001scene` 复用第 20 集成片文件名，必须先删夹具再恢复，否则引用冲突。
2. **补发布记录**：对全部 `upload_marks` 执行 M2 的同一派生规则（复用同一函数，不写第二套逻辑），使 09-29~10-02 四集进入分析口径。
3. **恢复第 39/40 集**：插入两条 `contents` 行，`video`/`audio` 指向盘上孤儿文件，`content`/`words` 取截帧识读文案与词表，`status='completed'`，`created_at` 取成片 mtime（09-24 19:12 / 09-25 19:31），`audit` 写 `{ recovered: { by, at, evidence: "orphan-render-frame" } }` 明示非原始生成档案。
   诚实边界：**不**给这两集造 `upload_marks`（无发布证据），因此它们会出现在 M3 的「未标记发布」提示里——这是正确状态，不是遗漏。

交付形态：`scripts/recover-publish-data.sql`（或 drizzle 脚本）+ 执行前 mysqldump 指引 + 只读对账 SQL。生产执行由用户决定与动手。

### M6　侧边栏折叠（独立分支，不与本修复混提）

- 状态：`lib/sidebar-collapsed.ts` 单例（`ref` + `localStorage` 读写，键 `lf.sidebar.collapsed`），不引入状态库。
- 布局：`App.vue:120` 的 `w-[238px]` 改条件类 `w-[238px]` / `w-[64px]`；分组标题 `<p>` 与 `RouterLink` 文字在折叠态隐藏，图标居中。
- 切换按钮：置于侧边栏右缘（跨边界压在主区左沿），`aria-label`/`aria-expanded` 齐备，键盘可达；**只作用于 `lg:` 以上**——小屏仍是抽屉形态，折叠按钮隐藏，不与 `drawerOpen` 竞争状态。
- 悬停名称：`title` 属性 + `aria-label` 已满足"悬停浮出名称"，不引入 tooltip 组件（reka-ui tooltip 会带来焦点管理与层叠成本，收益不抵）。
- 激活态：折叠态保留 `inset_3px_0_0` 左侧高亮条，图标本身加 `bg-sidebar-item`，保证"当前在哪"不依赖文字。

## 五、明确不做什么

| 不做 | 理由 |
|------|------|
| 把 `/insights/videos` 行集改成 `contents` 驱动 | M2 之后收益消失，只剩一行全「—」的噪音；用 M3 提示承担可见性 |
| 前端派生发布记录 | 5→1→1 的扇出证明后端是唯一收口点；前端派生漏掉所有非 UI 调用 |
| 新写 URL→作品 ID 解析器 | `extractWorkIdFromUrl` 已是单一事实源，重复实现会产生两套解析口径 |
| 为无链接标记伪造 `platform_video_id` | 违反既有"无真实值一律置空不造假"纪律 |
| 删标记时级联删发布记录 | 指标以 `publishRecordId` 为键，级联会毁掉已导入历史数据 |
| 给恢复的两集造 `upload_marks` | 无发布证据；让它们出现在「未标记发布」提示里才是正确状态 |
| 还原第 39/40 集的 `audit` 生成档案 | 候选词/重试历史不存在，伪造等于污染审计语义 |
| 改 `pageSize` 上限 100 的契约 | 那是后端校验，改它等于放宽已发布契约；前端循环取全量即可 |
| 侧边栏折叠引入 tooltip 组件库 | `title`+`aria-label` 已满足需求，层叠与焦点管理成本不抵收益 |
| 顺手重构 `Analytics.vue`（358 行单行表格模板） | 与本次根因无关，混提会放大回归面 |

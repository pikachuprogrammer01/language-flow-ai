## 二、本地开发（完整流程，已验证）

> **模式说明**：开发态 = 容器只跑 MySQL + 本地 `pnpm dev`（代码改动即时生效，**无需构建**）；
> 部署态 = `docker compose` 全栈（见 §六）。两者共用同一 uploads 目录（软链），
> 视频与上传标记在两种模式下完全一致。

```bash
# 1. 安装依赖
pnpm install

# 2. 启动 MySQL（容器，唯一常驻服务）
docker compose up -d mysql
# 容器名 language-flow-mysql，端口 3306，dev/dev 用户

# 3. 配置环境变量
cp .env.example .env

# 4. uploads 目录软链（本地与容器共享同一目录，避免「本地/容器视频不一致」；
#    软链丢失时重新执行）：
ln -s ~/language-flow-uploads packages/backend/uploads

# 5. 初始化表结构（首次或 schema 变更后；pnpm 不自动加载 .env，需显式传 DATABASE_URL）
cd packages/backend
DATABASE_URL="mysql://dev:dev@localhost:3306/language_flow" pnpm db:generate
DATABASE_URL="mysql://dev:dev@localhost:3306/language_flow" pnpm db:migrate
cd ../..

# 6. 启动前后端（两个终端；代码改动即时生效）
pnpm dev
# 后端 http://localhost:8080（GET /health 健康检查）
# 前端 http://localhost:5173
```

**注意**：
- **迁移**：本地 dev 不自动跑迁移（迁移只在容器 entrypoint 自动执行）；schema 变更后手动执行
  `DATABASE_URL="mysql://dev:dev@localhost:3306/language_flow" npx tsx src/db/migrate.ts`
- **端口冲突**：本地 dev 与容器 backend/frontend 都占用 8080/5173——切换模式前先停另一边
  （`docker compose stop backend frontend` 或 Ctrl-C 本地 dev；MySQL 容器保持运行）
- **限流**：100 次/分钟限流仅生产启用（`NODE_ENV=production`），本地开发不受限
- **上传标记**：按任务归属（`task_id`）关联，重新渲染后标记不丢失，各页面口径一致

**注意**：如果 MySQL 容器不是用本仓库 `docker-compose.yml` 启动的（如手动 `docker run`），
`dev` 用户可能不存在，需 root 补建：

```sql
CREATE USER IF NOT EXISTS 'dev'@'%' IDENTIFIED BY 'dev';
GRANT ALL PRIVILEGES ON language_flow.* TO 'dev'@'%';
FLUSH PRIVILEGES;
```

## 六、Docker 容器化部署（✅ 已验证 2026-08-18）

一条命令启动全部服务（MySQL + 后端 + 前端）：

```bash
docker compose up -d --build
```

| 服务 | 容器名 | 访问地址 | 说明 |
|------|--------|----------|------|
| frontend | language-flow-frontend | http://localhost:5173 | nginx 托管静态文件，反向代理 /api、/files、/doc、/health 到后端 |
| backend | language-flow-backend | http://localhost:8080 | Hono API + TTS + 视频渲染（含 Chromium + FFmpeg） |
| mysql | language-flow-mysql | localhost:3306 | MySQL 8.4（dev/dev，数据持久化） |

启动行为（entrypoint.sh）：

1. 等待 MySQL 就绪（healthcheck）
2. `tsx src/db/migrate.ts` — 应用 drizzle 迁移（幂等）
3. `tsx src/db/seed.ts` — 词库 seed（幂等，5999 词全量重灌）
4. 启动后端（`tsx src/index.ts`，与 dev 相同运行时）

### 环境变量（docker-compose.yml 可覆盖）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| LLM_BASE_URL | http://host.docker.internal:11434/v1 | Ollama 默认连宿主机（macOS/Linux extra_hosts 已配 host-gateway） |
| LLM_API_KEY | ollama | Ollama 不校验 |
| LLM_MODEL | qwen2.5:7b | 模型名 |
| CORS_ORIGIN | http://localhost:5173 | CORS |
| LOG_LEVEL | info | pino 日志级别 |

### 数据与文件

- 数据库：`mysql_data` 卷（可改用外部卷：`external: true`）
- 上传文件（audio/video/bgm）：绑定挂载 `${HOME}/language-flow-uploads` → 容器内 `/app/packages/backend/uploads`；本地 dev 经软链共用同一目录
- 前端同源部署：构建时 `VITE_API_BASE_URL=""`，所有请求走 nginx 代理

### 镜像与构建说明

- `Dockerfile.backend`：node:24-bookworm-slim + ffmpeg + fonts-noto-cjk（中文渲染）+ Chromium（npmmirror 下载，`PLAYWRIGHT_DOWNLOAD_HOST` 可覆盖）
- `Dockerfile.frontend`：node 构建（gen-api 生成 schema.d.ts → vite build）→ nginx:alpine
- 首次构建需拉取基础镜像；Docker Hub 不通时已在 OrbStack 配置 registry-mirrors（daocloud / hub.rat.dev）
- **构建时机**：构建较耗时（后端 pnpm install 全量），**确认代码验证通过后再构建**——
  日常开发/看页面用本地 dev（§二），`docker compose up -d --build` 仅用于部署

### 常见问题（容器化）

| 问题 | 处理 |
|------|------|
| 宿主端口被本地 dev 占用 | 先停 `pnpm dev`（8080/5173），再 `docker compose up -d` |
| 本地/容器视频不一致（标记 404「视频文件不存在」） | 确认软链存在：`ls -la packages/backend/uploads`；丢失则 `ln -s ~/language-flow-uploads packages/backend/uploads` |
| 旧库数据迁移 | 旧卷数据 `mysqldump` → 导入新容器（2026-08-18 实测 34 条记录无损迁移）；若旧库无 `drizzle_migrations` 表（非本仓库迁移工具建的），需先 `drizzle-kit` 打 baseline 或手动建表，否则 entrypoint 迁移会因表已存在失败 |

## 七、生产部署方向（规划）

| 组件 | 方案 |
|------|------|
| 后端 | Node 24 服务（`pnpm --filter backend build` → `node dist/index.js`），反向代理 Nginx/Caddy |
| 数据库 | MySQL 8.4（云 RDS 或自建），DATABASE_URL 指向生产库 |
| 前端 | `pnpm --filter frontend build` → 静态文件托管（Nginx/CDN），API 地址走环境变量 |
| 文件存储 | MVP：`uploads/` 本地盘 + Nginx 静态路由；生产化：S3 兼容对象存储（SPEC 已预留） |
| 视频渲染 | 部署机安装 Chromium（`playwright install chromium --with-deps`）+ ffmpeg |
| 日志 | pino 结构化日志 → stdout 采集（如 Loki/CloudWatch） |
| 反向代理 | /api → backend:8080；/files → uploads 静态；/ → frontend 静态 |

### 生产部署待办（接入时执行）

1. 确定服务器与域名，配置反向代理
2. 生产数据库初始化（db:migrate + db:seed 词库）
3. 设置 `NODE_ENV=production`、CORS_ORIGIN、密钥类环境变量
4. CI 增加构建产物上传（或服务器拉取构建）

## 八、常见问题（FAQ）

| 问题 | 处理 |
|------|------|
| `Access denied for user 'dev'` | 容器非本仓库 compose 启动，按 §二 补建用户 |
| `DATABASE_URL is not set` | pnpm 脚本不加载 .env，命令前显式 `DATABASE_URL=...` |
| 3306 端口占用 | `docker ps` 查看已有容器，或改 compose 端口映射 |
| 健康检查 404 | 正确路径是 `GET /health`（挂在 `/` 下），不是 `/api/health` |
| Chromium 启动失败（#18 后） | `pnpm --filter backend exec playwright install chromium` |

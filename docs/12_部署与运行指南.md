## 二、本地开发（完整流程，已验证）

```bash
# 1. 安装依赖
pnpm install

# 2. 启动 MySQL（首次会自动建 language_flow 库）
docker compose up -d
# 容器名 language-flow-mysql，端口 3306，dev/dev 用户

# 3. 配置环境变量
cp .env.example .env

# 4. 初始化表结构（首次或 schema 变更后；pnpm 不自动加载 .env，需显式传 DATABASE_URL）
cd packages/backend
DATABASE_URL="mysql://dev:dev@localhost:3306/language_flow" pnpm db:generate
DATABASE_URL="mysql://dev:dev@localhost:3306/language_flow" pnpm db:migrate
cd ../..

# 5. 启动前后端
pnpm dev
# 后端 http://localhost:8080（GET /health 健康检查）
# 前端 http://localhost:5173
```

**注意**：如果 MySQL 容器不是用本仓库 `docker-compose.yml` 启动的（如手动 `docker run`），
`dev` 用户可能不存在，需 root 补建：

```sql
CREATE USER IF NOT EXISTS 'dev'@'%' IDENTIFIED BY 'dev';
GRANT ALL PRIVILEGES ON language_flow.* TO 'dev'@'%';
FLUSH PRIVILEGES;
```

## 三、环境变量清单（.env.example 全字段）

| 变量 | 示例 | 必填 | 说明 |
|------|------|------|------|
| PORT | 8080 | 否 | 后端端口 |
| CORS_ORIGIN | http://localhost:5173 | 否 | CORS 允许来源（index.ts 读取，默认 http://localhost:5173） |
| DATABASE_URL | mysql://dev:dev@localhost:3306/language_flow | ✅ | MySQL 连接串 |
| LLM_BASE_URL | http://localhost:11434/v1 | 否 | LLM 兼容端点（Ollama 本地，docs/14；未配置时 /api/content/generate 返回 503） |
| LLM_API_KEY | ollama | 否 | LLM key（Ollama 不校验，任意值） |
| LLM_MODEL | qwen2.5:7b | 否 | LLM 模型名 |
| RENDER_TEMP_DIR | /tmp/language-flow-render | 否 | 渲染临时目录（#18） |
| LOG_LEVEL | debug | 否 | pino 日志级别 |

## 六、生产部署方向（⏳ 未实施，规划）

| 组件 | 方案 |
|------|------|
| 后端 | Node 24 服务（`pnpm --filter backend build` → `node dist/index.js`），反向代理 Nginx/Caddy |
| 数据库 | MySQL 8.4（云 RDS 或自建），DATABASE_URL 指向生产库 |
| 前端 | `pnpm --filter frontend build` → 静态文件托管（Nginx/CDN），API 地址走环境变量 |
| 文件存储 | MVP：`uploads/` 本地盘 + Nginx 静态路由；生产化：S3 兼容对象存储（SPEC 已预留） |
| 视频渲染 | 部署机安装 Chromium（`playwright install chromium --with-deps`）+ ffmpeg |
| 日志 | pino 结构化日志 → stdout 采集（如 Loki/CloudWatch） |
| 反向代理 | /api → backend:8080；/files → uploads 静态；/ → frontend 静态 |

### 生产部署待办（接入时执行）

1. 确定服务器与域名，配置反向代理
2. 生产数据库初始化（db:migrate + db:seed 词库）
3. 设置 `NODE_ENV=production`、CORS_ORIGIN、密钥类环境变量
4. CI 增加构建产物上传（或服务器拉取构建）

## 七、常见问题（FAQ）

| 问题 | 处理 |
|------|------|
| `Access denied for user 'dev'` | 容器非本仓库 compose 启动，按 §二 补建用户 |
| `DATABASE_URL is not set` | pnpm 脚本不加载 .env，命令前显式 `DATABASE_URL=...` |
| 3306 端口占用 | `docker ps` 查看已有容器，或改 compose 端口映射 |
| 健康检查 404 | 正确路径是 `GET /health`（挂在 `/` 下），不是 `/api/health` |
| Chromium 启动失败（#18 后） | `pnpm --filter backend exec playwright install chromium` |

# 24 配音音色治理：可配置清单 + 错误分类重试

> 状态：已实施（本仓工作树，尚未发布到生产）
> 关联：docs/08（TTS 服务设计）、docs/22（数据分析真实闭环）、SPEC §5.2 / §十
> 触发事实：2026-10-12 微软下线旧合成端点，切到 `api.msedgeservices.com` 后 8 个 Edge 音色中
> 晓辰 / 晓涵 / 晓梦 稳定「连上但不回音频」，晓晓等 5 个正常

## 一、目标

1. 音色清单变成**数据**，不写代码就能上下架某个音色，界面能操作
2. 被下架的音色不出现在任何下拉里，也就选不到
3. 配音失败按原因分流：音色不可用不再白重 3 次，限流退避而不是继续打满
4. 界面能「测一次」，用事实决定要不要上线一个音色，而不是猜

## 二、非目标

- 不做本地引擎兜底（本轮由用户明确推迟）。宿主机 `say` + `ffmpeg` 可用、容器可回调宿主这两点已验证，
  降级点在本方案里预留但不实现
- 不引入第二个云端 TTS
- 不改 `GET /api/tts/voices` 既有字段（只新增字段，向后兼容）

## 三、数据模型

新表 `tts_voices`（迁移 0013，纯加法）：

| 列 | 含义 |
|---|---|
| `id` | Edge 音色名（如 `zh-CN-XiaoxiaoNeural`），主键 |
| `label` | 界面显示名（晓晓（女·温暖）） |
| `gender` | 女 / 男 |
| `engine` | `edge` \| `local`，本地引擎预留位 |
| `enabled` | 是否上架 |
| `last_check_at` | 最近一次「测一次」时间，NULL = 从未测过 |
| `last_check_status` | `ok` \| `no_audio` \| `rate_limited` \| `handshake_failed` \| `error` |
| `last_check_detail` | 失败原因原文或音频时长，用于界面提示 |

种子数据 = 现清单 8 条 Edge 音色，其中晓辰 / 晓涵 / 晓梦 `enabled=0` 且 `last_check_status='no_audio'`。

**单一来源**：`lib/tts-catalog` 现在是硬编码清单，被 `routes/tts.ts` 与 `routes/video-analytics.ts`
（发布配置音色白名单）共用。改为读表后两处必须同源，否则会出现「界面能选但发布被拒」或反向不一致。
`availableVoices()` 保留为纯函数签名，数据来源换成 service，带 30 秒内存缓存避免每次合成打库。

## 四、API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/tts/voices` | 已有；响应新增 `engine`、`checkedAt`、`checkStatus`，并新增 `all`（含下架项，供管理页用） |
| PATCH | `/api/tts/voices/:id` | 上下架：`{ enabled: boolean }` |
| POST | `/api/tts/voices/:id/probe` | 「测一次」：固定短句合成，写回 `last_check_*`；成功产物写后立即删除，不留孤儿文件 |

`synthesizeSpeech` 前置校验：`voice` 不在 `enabled` 清单 → 直接 400「该音色已下架」，
不再打到 Edge 换回一个 500。

## 五、重试分类

现状：任何失败都固定重 3 次（含 500ms/1000ms 退避），限流时自我放大，音色不可用时白等 7 秒。

| 类别 | 识别 | 策略 |
|---|---|---|
| `VOICE_UNAVAILABLE` | 握手成功但零音频帧结束（`No audio data received`） | **不重试**，500 文案点名「该音色在当前端点不可用，可在配音音色页测一次或换音色」 |
| `RATE_LIMITED` | HTTP 429 | 退避 2s / 6s，最多 2 次；仍失败 → 500「配音服务限流，稍后重试」，并在错误里带建议重试时间 |
| `HANDSHAKE_FAILED` | 403 / 5xx / TLS 与网络错误 | 重试 1 次；仍失败 → 500 透出原文（沿用现有「真实原因透给前端」约定） |
| `LOCAL_ENGINE_MISSING` | 非 darwin 环境选到 `local` 音色 | 不重试，500 文案点名容器无 `say` |

分类函数是纯函数（输入错误对象/状态码，输出类别 + 是否可重试），单测不依赖网络。
错误分类结果写进日志字段 `ttsErrorClass`，便于以后按类别统计。

## 六、界面

侧边栏「运营」组新增入口「配音音色」→ `/tts-voices`：

- 表格每行：显示名 / 引擎 / 状态（上架中·已下架）/ 最近实测结果与时间 / 操作
- 操作两个按钮：「测一次」（转圈到出结果，结果就地更新）、「下架 / 上架」开关
- 下架项整行灰显但保留在列表里（否则以后无从上线）
- 顶部一行说明：下架只影响新任务，已生成内容不回滚

## 八、验收

- 单测：分类纯函数四类全覆盖；`enabled` 过滤；上下架；probe 写回
- 测试栈：把晓晓下架 → 下拉里消失、直接 POST 该音色返回 400；点「测一次」晓涵显示「无音频」

## 十、实施结果与偏差

- 路径段用 `{id}` 而非 `:id`：仓库自己的 OpenAPI 规范门禁只认花括号动态段
- `probe` 测不出音频也返回 **200**（结论就是结果），只有「音色不在目录里」才 404
- 404 响应声明了 `apiErrorSchema`，否则构建期 `tsc`（declaration 模式）会因分支返回把状态推成
  `200|404` 而报错——`typecheck`（`--noEmit`）抓不到，只有 `build` 抓得到
- 迁移文件里 CREATE TABLE 与种子 INSERT 之间必须有 `--> statement-breakpoint`，
  否则 drizzle 把整个文件当一条语句发给 MySQL
- 管理页把 DataTable 分页设为 50：目录 11 条，默认每页 10 会把尾部音色分到第二页，
  运营看不出「到底有几个音色可选」
- 默认 E2E 套件**不点**「测一次」：那会真打微软端点，外网抖动会把七步门禁染成不稳定红灯；
  全量音色实测留给后续独立的 `pnpm tts:doctor` 手动命令（本次未实现）

> 版本：V1.0 · 2026-08-17
> 目标：**完全免费** + **无缝切换**（不改源代码，仅 Dify 后台设置）+ **Docker 可打包**
> 关联：dify/（Workflow）、docs/05（Workflow 设计）

## 一、决策

| 项 | 决策 |
|----|------|
| 主力模型 | **Agnes AI**（https://agnes-ai.com，免费 Omni-Modal AI API，用户确认 2026-08-17） |
| 兜底模型 | **Ollama 本地**（qwen2.5:7b，零成本离线，当 Agnes 停止免费时切换） |

## 二、Dify 模型供应商接入

### 2.1 Agnes（主力）

1. 注册 https://console.agnes-ai.com 获取 API key
2. 确认 Agnes 的 API 端点是否 **OpenAI 兼容**（`/v1/chat/completions` 格式）——注册后在控制台文档确认
3. Dify → 设置 → 模型供应商 → **OpenAI-API-compatible**（自定义供应商）
   - `API Key` = Agnes key
   - `API Endpoint URL` = Agnes 的 OpenAI 兼容端点（如 `https://api.agnes-ai.com/v1`，以控制台文档为准）
4. 模型名称填 Agnes 支持的模型 ID
5. 在「默认模型」中把 Workflow 用到的模型（生成故事/词汇的 LLM）设为该模型

### 2.2 Ollama（兜底）

```bash
# 本机安装（推荐，Metal 加速）
curl -fsSL https://ollama.com/install.sh | sh   # 或 brew install ollama
ollama pull qwen2.5:7b                           # ~4.7GB，后台下载

# 或 Docker 方式（与平台同容器网络）
docker run -d --name ollama -p 11434:11434 -v ollama-data:/root/.ollama ollama/ollama
docker exec ollama ollama pull qwen2.5:7b
```

Dify 接入（OpenAI-API-compatible）：
- 本机安装：Endpoint = `http://host.docker.internal:11434/v1`（Dify 在 Docker 时）
- Docker 方式：Endpoint = `http://ollama:11434/v1`（compose 同网络）
- API Key 任意（如 `ollama`），模型名 `qwen2.5:7b`

### 2.3 切换操作（不改代码）

Dify 后台 → 设置 → 模型供应商 → **默认模型** → 选择 Agnes / Ollama 对应的模型。
Workflow 中引用的是「默认模型」的别名（如 `LLM` 节点），切换供应商后**自动生效**，无需改 Workflow 或代码。

## 三、Docker 打包说明

| 组件 | 打包方式 | 网络 |
|------|----------|------|
| Dify（Workflow + 前端） | 官方 docker-compose（dify/dify） | 默认网络 |
| 后端（本仓库） | 现有 Dockerfile（Hono + MySQL） | 默认网络 |
| MySQL | 现有容器（8.4） | 默认网络 |
| Ollama（可选，兜底） | `ollama/ollama` 镜像 + `ollama-data` volume | 同网络，`http://ollama:11434/v1` |
| Agnes | 无需容器（纯 HTTP API），key 存环境变量 | 外网 |

compose 片段（兜底 Ollama，**随 compose 自动启动，无需手动开**）：

```yaml
  ollama:
    image: ollama/ollama
    restart: unless-stopped      # 随 Docker 自动拉起，挂了自动重启
    volumes:
      - ollama-data:/root/.ollama
    ports:
      - "11434:11434"
volumes:
  ollama-data:
```

> ⚠️ 注意：macOS Docker Desktop 容器内 Ollama **无 Metal GPU 加速**（CPU 跑 7B ≈ 8-12 tok/s）；
> 追求速度时本机装 Ollama（Metal，20-30 tok/s），Dify 连 `host.docker.internal:11434`。

### 3.1 Ollama 启动方式（避免遗忘，用户确认 2026-08-17）

| 阶段 | 启动方式 | 手动操作 |
|------|----------|----------|
| **当前（本机开发）** | `nohup ollama serve > ~/ollama.log 2>&1 &`（或另开终端跑 `ollama serve`） | 每次开机后跑一次；也可 `brew services start ollama` 设开机自启，之后不用管 |
| **后期（全容器化）** | `docker compose up -d`，ollama 容器随 compose **自动启动**（`restart: unless-stopped`） | **无需手动开 ollama**，模型存 `ollama-data` volume，pull 一次永久有效 |
| **后期（本机 ollama + 容器其他）** | `brew services start ollama` 开机自启 | 无需手动操作（Dify 连 `host.docker.internal:11434`） |

> 决策：用户更在意速度 → 当前用本机 ollama（Metal 加速）；后期全容器化时 ollama 自动随 compose 起，二选一均可（容器内无 Metal，速度约一半，届时按需选择）。

## 四、成本与切换预案

| 场景 | 动作 | 成本 |
|------|------|------|
| Agnes 免费额度充足 | 默认使用 | 0 元 |
| Agnes 限流/停止免费 | Dify 后台把默认模型切到 Ollama | 0 元（本地） |
| 两者都不可用 | 可再接入智谱 GLM-4-Flash 免费 / Gemini 免费 tier | 0 元 |

**验收**：切换供应商后，重新生成一条视频内容（Dify Workflow 跑通），确认新模型生效、输出质量可接受。

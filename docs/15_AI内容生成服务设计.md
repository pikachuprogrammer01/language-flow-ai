## 一、目标

用户输入主题/等级 → 后端调用 LLM 生成「情景词汇阅读」内容（中文故事 + 四六级词嵌入）→
词库校验 → 返回标准 ContentDTO（scene_word 模板）。**零外部平台依赖，纯 HTTP 调用 LLM。**

## 二、接口契约

### POST /api/content/generate

请求体：

```json
{
  "topic": "森林探险",
  "level": "CET4",
  "wordCount": 8,
  "targetDuration": 60
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| topic | string | ✅ | 故事主题，≤ 50 字 |
| level | "CET4" \| "CET6" | ✅ | 四六级等级 |
| wordCount | int 3~15 | 否 | 期望词汇数（默认 8；CET6 建议 3-8） |
| targetDuration | int 15~300 | 否 | 目标视频时长（秒，影响段数建议） |

响应：

```json
{
  "content": {
    "id": "cnt_20260817_000001",
    "template": "scene_word",
    "title": "职场英语：读一个科技创业故事",
    "level": "CET4",
    "targetDuration": 60,
    "content": [
      {
        "text": "奥斯丁在一家科技establishment工作，负责equip实验室的先进设备。",
        "words": [{ "word": "establishment", "meaning": "机构", "level": "CET4" }]
      }
    ],
    "words": [],
    "style": { "background": "white" },
    "voice": { "id": "female_01" },
    "status": "content_ready",
    "createdAt": "...", "updatedAt": "..."
  }
}
```

错误：400（参数校验）/ 500（LLM 超时、JSON 解析失败、词库校验后无可用词）。

## 三、处理流程（后端 service，V3 代码注入版）

```
POST /api/content/generate（Zod 校验）
  → content.service.generateSceneWordContent({topic, level, wordCount, targetDuration})
     1. 阶段一（候选词）：LLM 产出主题相关词（15 个）→ 词库校验命中 → 高频池随机补足至 2×wordCount
     2. 阶段二（故事）：模型只写纯中文故事（JSON：{topic, title, segments:[{text}]}）
     3. JSON 容错解析（extractJson 迭代截断，容忍围栏/杂质/尾部字符）+ zod 结构校验
     4. 代码注入：扫描候选词词库释义的中文义项在 text 中的出现 → 原位替换为英文词
        （词必在词库、逐字在文本；义项按长度降序防子串冲突）
     5. 代码验收：
        - 主题相关度：模型回显 topic 与输入主题字符覆盖率 ≥ 50%（防"完全对不上"）
        - 词汇数：注入成功数 ≥ 5（用户硬约束：每篇 5-20 词；上限 20 由注入 break 保证）
     6. 验收失败 → 把具体原因反馈给模型重试（最多 3 次，每次全新对话无上下文污染）
     7. 组装 ContentDTO（template=scene_word, status=content_ready）
  → 返回 ContentDTO
```

**设计动机（2026-08-17 实测）**：qwen2.5:7b 写"中文故事 + 直接嵌英文词"执行不力（词数 1-2、
词与文本不对应、主题被无关候选词带偏）。**V3 把元任务从模型移除**：模型只写纯中文（最擅长），
英文词由代码按词库释义映射注入——文案自然、主题正确、词 100% 来自词库且逐字在文本。

**段数建议**：targetDuration ≤ 30s → 1 段；≤ 90s → 2 段；其余 3 段（每段 50-100 字）。

**失败兜底**：3 次重试仍失败 → 500，响应体携带可读原因（主题偏离/词汇不足/JSON 非法），
前端展示给用户/人工审核，可点击重新生成（前端"生成视频"按钮再点即重新生成）。

## 四、LLM 抽象（llm.service）

- OpenAI 兼容 Chat Completions：`POST {LLM_BASE_URL}/chat/completions`
- 环境变量（全部可选，未配置时接口返回 503 提示配置）：

| 变量 | 示例 | 说明 |
|------|------|------|
| LLM_BASE_URL | http://localhost:11434/v1 | 兼容端点（Ollama 本地；后端在 Docker 时用 host.docker.internal） |
| LLM_API_KEY | ollama | Ollama 不校验，任意值 |
| LLM_MODEL | qwen2.5:7b | 模型名 |

- 切换：改环境变量即可（换 Ollama 模型/换兼容端点），**代码零改动**；前端设置页（阶段 5）后续可写配置
- 超时 60s；响应非 JSON / 解析失败 → 500

## 五、Prompt 规范（scene_word 生成，V3）

角色：英语短视频内容创作者。
要求（源自《情景词汇阅读视频模板设计规范 V1.0》§七 + 用户 2026-08-17 定稿 + V3 重构）：

1. **模型只写纯中文故事**（英文由代码注入，模型不写英文、不写词汇数组）
1b. **词汇数硬约束（2026-08-17 用户确认）**：每篇 ≥5 且 ≤20 词——候选词三来源（主题相关词 →
    通用叙事词表 26 词 → 高频池随机）保证故事里自然出现的中文词义足够多；注入上限 20；验收下限 5
2. 故事情节连贯、生活化，**必须紧紧围绕主题 = topic**，标题呼应主题
3. 写作时自然使用候选词汇的中文含义相关的内容（候选词清单附在 prompt 尾部）
4. 标题：**主题式**（点明主题+学习内容，自然不夸张，≤ 20 字）
5. 正文段数按 targetDuration 建议（≤30s=1 段，≤90s=2 段，其余 3 段，每段 50-100 字）
6. 输出严格 JSON（含 topic 回显，供代码验收主题相关度）：

```json
{
  "title": "职场英语：读一个科技创业故事",
  "segments": [
    {
      "text": "奥斯丁在一家科技establishment工作。",
      "words": [{ "word": "establishment", "meaning": "机构" }]
    }
  ]
}
```

6. words 的 word 必须**逐字出现在**对应 segment 的 text 中（渲染高亮依赖）

## 六、错误处理

| 场景 | 行为 |
|------|------|
| LLM 未配置（env 缺失） | 503，提示配置 LLM_BASE_URL/LLM_API_KEY/LLM_MODEL |
| LLM 超时（>60s）/ 网络错误 | 500，可重试 |
| 返回非 JSON / 结构不符 | 500（记录原始输出便于调试） |
| 词汇全部未通过词库校验 | 500（提示词库为空或 LLM 输出不合法） |
